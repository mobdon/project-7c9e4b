# NFSU2 Driving Tools: experimental v0.42.8 draft

## 0.42.8 — synthetic near-miss awards and optional NOS top-up

Adds **Synthetic near miss → Award once** and a separate **Keep NOS topped up** switch. Both use the verified native award service for the current game module, memory and session. Unsupported builds and failed preparation leave them unavailable. Top-up starts off, is outside saved profiles and must be enabled on the current page.

The synthetic award has no speed threshold. It uses the game's original style-award routine on the current owned car. Mailbox ownership starts after driving initialization; car changes cancel an unclaimed request, and a restarted session receives a new bridge.

Direct automatic NOS refill remains disabled. The optional loop samples effective NOS, including elapsed consumption, before each synthetic request. It waits at full or overfull, resumes after consumption, allows only one outstanding request and waits at least 250 ms after confirmation before another. Missing or invalid resource state prevents dispatch. F7/F9, a changed car/session and uncertain or style-only outcomes turn top-up off; focus and permission loss pause it and request cancellation.

Synthetic awards also change style points and combo multipliers. The result distinguishes the native style award from whole-tick style/NOS changes; those NOS changes are not isolated event-specific credit. A queued award can still finish if native work has already begun. Native overshoot remains visible; page sampling cannot guarantee the resource stays below full until native consumption. Unknown, stale, mismatched or timed-out requests never retry automatically.

This is a working source update. Packaging, installation and live gameplay verification have not been performed. Historical offline results below apply to their original source pins; motion generated by this extension has not yet been cleared by a complete native trajectory test.

### Free-roam corner-speed assist

A separate, experimental opt-in reduces the native planner's curvature-limited speed for upcoming free-roam corners. It does not replace steering or road paths. Its bounded factor is **0.60–0.95**, starting at **0.80**. Straight/gentle segments retain their native speed cap. This factor is a tuning hypothesis, not a measured optimum.

**Sharp-turn margin** adds 0–25% extra reduction, starting at 15%, according to how far the native corner speed falls below its maximum cap. Tighter upcoming bends receive more margin. The combined formula is `nativeCornerSpeed × baseFactor × (1 − margin/100 × (1 − nativeCornerSpeed/nativeMaximumSpeed))`. At 0%, it follows the v0.13 calculation exactly. With the strongest settings the effective factor can approach 0.45×; it never changes a straight-cap result. This adjusts the original planner’s speed cap, not its steering or proven sampling distance. Begin with normal 1× pace and power/grip changes off, comparing 0% and 15% on the same solo route.

It applies only to the current, owned AI driver's private main route in native free roam. Races, outruns, drag, drift and the Dyno Shop are excluded. Changing its enabled state, factor or sharp-turn margin rebuilds AI through a full native OFF/manual/ON handoff, because the game caches route speed caps. Free-roam/race transitions also rebuild before rearming.

**Corner status:** Armed means a request is present, not that a qualifying native reduction has been confirmed. Straight/gentle calls and guarded calls add no hit. Occupied command memory and observed drift exclusion are reported separately. The crash log now records bounded corner hits, request state, applied factor and those two observable guards. Confirmed pace is a different acknowledgment and does not prove corner assist ran. For diagnosis, use 1× pace; 0.95× corner factor reduces a qualifying corner cap by only 5%. A persistent no-hit result after bends is still unresolved without live telemetry.

It may help turn entry but cannot repair a bad route, prevent crashes, guarantee a clean corner or improve lap times. More power, grip or pace may undermine it. Live braking, route rebuilding and handling improvements remain unverified. Start conservatively and keep F7 available.

### Full per-race preset tuner

Use the **solo Performance Tuning main screen** on exact93af6ccb,943ee537,bdc9cbc2,b1efa173 or ed8d3359. Back up your save, select a race preset in the game, then enable the tuner. It never buys upgrades, switches the game's preset, enters a race or presses Save Profile.

1. **Load selected preset** captures the current car, installed parts, working tune and selected visit tune on the game thread. The editor displays all 41 settings in their native categories and disables fields locked by installed parts/native rules.
2. Change sliders and press **Preview draft**. Native setters and rebuild/measurement functions run only in a separate memory copy. The preview shows accepted values, including native coupled changes, and comparable before/after estimates. Your live setup remains unchanged.
3. Alternatively choose a measured goal and press **Find tune**. Peak power/torque searches ECU/turbo; 0–60, 0–100 and top speed search gearing plus ECU/turbo. Search is capped at 48 trials. It keeps manual suspension, brake, tire, aero and NOS choices, but does not optimize their handling or lap-time effects. A faster estimated acceleration can reduce top speed; inspect all results.
4. **Stage selected preset** is an explicit separate action. It accepts only the last successfully evaluated candidate, on the same car, preset, installed parts and unchanged setup/visit/record. A game-thread transaction copies just the current 41-byte tune and selected 41-byte visit tune. Other presets and the saved-car record are not written by this action.
5. Start the game's own **Test Run** to refresh driving physics and check the tune. Merely exiting the tuning screen is not a verified rebuild. Use the game's **Save Profile** to persist changes. The game's save can commit all five visit presets, so the tuner warns when other visit presets differ from their stored record. “Save ready” is not a successful save confirmation.
6. **Restore previous** needs the same car, preset, parts and exact last-staged tune. It restores the original current and selected visit tunes, even when those originally differed. A known native commit of this exact selected tune is accepted; unrelated record changes are refused. Restore does not undo disk saves. Use Test Run and Save Profile again if you want the restored state refreshed and persisted.

Each car/preset has separate guarded restore state while the page stays open. A car replacement, manual edits, changed parts or an unknown record change invalidates stale results. Reload loses this temporary restore history. Native unlocked gear counts and tuning rules remain authoritative; no sixth gear is invented. Sliders display −100 to +100 around the game's neutral value, stored internally as bytes 0–200. These are normalized settings, not physical units.

The measurements are native estimates, not lap times or on-track benchmarks. Handling controls and NOS expose native settings without a proven per-race optimal objective. There are no claimed “perfect” race presets, global optimum, guaranteed wins or proven save/reload result. The previous peak-only dyno tool remains on older supported builds with its existing guarded Apply/Restore flow.

Cancel, F9, closing the panel, blur, a hidden tab, leaving the page or disabling the tuner cancels ongoing work. Driving effects pause during work, with their selections retained. **F9 does not undo a tune already staged.** Re-enable the tuner and use Restore previous while its baseline remains valid. A timed-out game-thread request has an uncertain outcome and disables further writes until reload; inspect the game rather than blindly retrying.

The private evaluator extracts only reviewed native functions from the exact game module already downloaded by the browser. It has its own memory, checked capture ranges, write allowlist and operation budget. Capture/stage/restore run through a command-gated frame prefix with no native calls and no profile-file writes. This bounds the reviewed path but is not a guarantee against browser exhaustion, unrelated game faults or live object-lifetime races.

### Power and handling

- **Automatic NOS refill:** unavailable while near-miss integration is tested offline. Saved selections cannot enable it. Game-earned NOS and native NOS use remain available.
- **Power boost:** 1.0×–3.0× engine and nitrous torque. Starts at 1.5×. Repeated updates do not compound. More power can worsen wheelspin and handling.
- **Remove stock limiter:** removes the stock MPH governor while enabled. Gearing, drag and redline still limit speed. Upgraded cars may already lack that governor.
- **Extra grip:** 1.0×–2.0× all four tyre-force factors. Starts at 1.3×. It is not auto-steering, yaw damping, corner avoidance or guaranteed handling. High grip can cause abrupt behavior or rollover. It pauses in drift mode/races.
- Power and grip restore only fields still owned by the extension. They wait for three matching samples before applying to rebuilt car data. Changed external tuning is preserved rather than overwritten. Pause/off restores owned values when the original live objects remain valid.
- **Drift assist:** uses the game's real drift-event input and waits for its handling confirmation. Solo free roam only, with game menus closed. It is not perfect-drift automation. Power/grip restore before the native tuning rebuild; settings stay selected. Drift uses its own switch, including after F9.

### Wall / barrier pass-through

**Handling & collisions → Wall pass-through** is independent of AI and **solo-only**, even with Online/LAN tools allowed. Turn **Free roam with others** off, or use a solo race.

Only contacts between your car and verified near-vertical static track polygons are skipped, using the native wall threshold `abs(normal.z) < 0.1`. Ground, ceilings, ramps/slopes and movable props retain the original collision path. Cars retain it unless the independent Car no-clip option is enabled. Sloped faces and movable barrier props remain solid. This is not unrestricted flight or universal noclip. The game's native Ghost setting affects cars, not walls; the extension leaves that setting unchanged.

A selected checkbox is not proof of contact filtering. Its status first says Armed, then counts contacts actually skipped by the native hook. Test a plain vertical wall and neon barrier at low speed; verify ground/ramp and car collisions yourself. Coverage has not been live-verified.

You may leave the drivable map, miss checkpoints or get stuck inside scenery. Native recovery may reposition you after a reset. **Turn it off only when clear of a wall.** Off/F9/reload restores the original collision path. It does not change shared map objects or body collision flags.

### Solo Car no-clip

**Handling & collisions → Car no-clip** is separate from Wall pass-through and is solo-only. It matches confirmed native car collision bodies paired with the current local player's car, whether driven manually or by AI. It does not skip collisions between other cars. Walls, ground and props retain their normal path unless the wall option separately applies.

It starts off after reload and reports Armed until a supported contact is actually skipped. Turn it off only once clear of other cars. F9 stops it. No body flags or shared map objects are changed. Native constructor/category and current wrapper tests pass, but real traffic/racer collisions have not been live-verified.

### Online traffic no-clip

**Handling & collisions → Online traffic no-clip** is a separate switch, available on exact builds **93af6ccb and 78e2bb69**. It requires online free roam and matches native NPC traffic paired with your local car, driven manually or by AI. It excludes native player-slot cars even if they use a traffic model or traffic driver flag, plus ordinary AI racers, every race category, outruns and Online/LAN races. Other players and rejected contacts retain the game's original collision logic, including any native Ghost choice you made. Walls, ground, props, body flags and map objects are unchanged.

This switch starts **off after every reload**, even if previously selected. It needs its own explicit opt-in; **Allow Online/LAN tools** never enables it. That general permission is not required for this narrowly scoped online-free-roam traffic switch. Solo Car no-clip stays independent. The status distinguishes Armed from observed traffic contacts skipped. F9 stops and clears it; blur, hidden tabs, dyno work and unavailable driving state pause it. Turn it off only when clear of traffic.

No live online collisions, peer synchronization or server acceptance have been verified. It changes local contact resolution, not the traffic simulation or server rules. Follow the site's rules and use an explicitly permitted private test. A selected or Armed switch is not proof that a real contact was skipped.

### Manual drag assist

A separate, optional throttle / RPM-threshold shift helper **while you steer**. Uses the default Arrow Up and Left Shift bindings. Its extension-driven NOS helper is unavailable while automatic refill is disabled. Set shift RPM for your car; 6500 is only a starting point, not learned perfect shifting.

Manual drag assist never runs while automatic drag AI is requested, including countdown and failed/unavailable AI. It will not silently substitute synthetic inputs. With Automatic AI off, manual drag waits for native ownership to clear and a human driver to be confirmed. Countdown permits throttle only; shifts wait for GO. It does not choose lanes or avoid obstacles. F7/manual takeover pauses it until its switch is toggled again.

### Diagnostics

#### Local crash log

Open **Driving tools → Session & diagnostics → Crash log → Export crash log**. This downloads `nfsu2-driving-tools-diagnostics.json` on your computer. Nothing is automatically sent or uploaded. **Clear log** removes this tab's retained diagnostic history; recording then continues.

The logger starts when this extension page loads. It records recent tool choices/factors, sampled game mode and driver state, page/game-worker lifecycle, classified errors, numeric WebAssembly function/offset locations and line numbers from known script files. It does not capture raw console logs, error messages, URLs, credentials, names, saves, keyboard input or network traffic. It never changes game memory or enables a tool.

The newest **180 events, limited to 64 KiB of stored JSON**, are kept in same-tab session storage. State is sampled on discrete changes (at most four times a second), moving native scalars about every two seconds, and a baseline snapshot every five seconds while driving; rapid repeated page errors are capped. Older entries are discarded and the file reports the count. Export soon after a problem. Reloading the same tab normally retains the log; closing the tab, clearing site data, browser recovery behavior or blocked/full storage can lose it. The menu reports when the log is memory-only. The site's own scripts can access this same-origin session storage, so it is not an extension-private vault.

**Capture limits:** this cannot recover crashes that happened before the logger was installed. A full browser/tab/GPU crash, freeze or forced close may prevent any final event. This is a history of observations, not a complete crash dump or proof of the crash's cause; the last snapshot may precede the failure. Free-text errors are deliberately omitted for privacy, so unfamiliar errors appear as `other`. Also export the game's own **Download log** for native game details. This logger does not fix the reported crash or establish that the game is safe.


The read-only traffic/barrier tester reads nearby car objects and the enabled barrier-line table. It is incomplete: it does not fully classify traffic/racers, shapes, props, road geometry, elevation or safe lanes. No detected obstacle does not imply a safe road.

## Privacy, implementation and rollback

The extension matches only `https://nfsu2.xyz/*`. No account, history, debugger or broad website permissions. It stores its own preferences and a bounded, sanitized diagnostic history in namespaced same-tab session-storage entries. Nothing is uploaded. Its only added request is a same-origin `/game.json` compatibility read; it inspects the game's own module response during loading. No analytics, remote code or game assets are bundled.

- AI calls native `Player::AutoPilotOn`, `AutoPilotOff` and `SetInputMode` through the game's existing CPU-preserving game-thread dispatcher. It never invokes native game functions concurrently from the page thread.
- Normal drag opponents use driver type 3 / physics type 1, while player autopilot initially asks for physics type 3. The retained drag handoff corrects only the eligible local car, verifies both types and rolls back on failure.
- The page's automatic AI switch supplies the exact drag-permission word only when drag is detected. The native permission and full-physics checks are still required. The pace hook never modifies drag.
- Mode switching publishes OFF and verifies the native heartbeat acknowledgement, cleared ownership and restored manual driver before rearming. Identity, native subtype/track flags and race/free-roam mode are part of that comparison. Native Off/On rebuilds the private driver route.
- Command memory stays at `0x00d0d100` (104 bytes used on modern Drag-heat profiles;92 bytes on older profiles) and walls at `0x00d0d180` (40 bytes), under sequence locks. Cars use `0x00d0d1c0` (40 bytes); the existing final word selects the independent online traffic/player modes on 93af6ccb and 78e2bb69. The corner record is at `0x00d0d200` (64 bytes, CNR3), and dyno uses `0x00d0d300..0x00d0d4ff`. These do not overlap. Native scalar-reference/allocator analysis supports using these gaps, but exclusive allocation has not been formally proved and unknown computed writes remain a risk. Cold empty/owned checks and post-attachment ownership guards reduce, not eliminate, that risk. The current-build patch targets the main-loop bridge, player pace, contact resolver, corner/braking helpers, native drag action/input selectors, native Drift damping expression and three guarded nitrous acceptance sites. Original native instructions remain preserved around the scoped changes.
- The full tuner additionally grows the game memory by an owned 16 MiB snapshot buffer, records its module/memory identity and uses the existing dyno mailbox for commands. Snapshot growth is not undone until reload. Native evaluation runs in separate memory with guarded reads/writes and execution fuel. Staging does not call a game physics rebuild or save helper.
- Wall filtering prefixes `sub_005b2610` and preserves the full original resolver for every rejected contact. Body type/vtable, reciprocal car/face pointers, finite unit normals and pair identities are checked. Native `roam_game_online_here()` always blocks wall filtering during multiplayer free roam. The separate latest-build traffic path also calls the exact native read-only player-slot helper and excludes recognized player cars.

For rollback, copy your complete previous extension files into the same loaded folder, Reload its existing extension card, then refresh the game. Keep the backup outside the loaded folder and never enable both copies. The previous release remains subject to its build-compatibility checks. This restores extension code, not game progress or changed settings. See `UPDATE-WINDOWS.txt`.

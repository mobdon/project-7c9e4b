Current page contract for v0.38.7: Native calculated catch-up always calls this observer with `enabled:false, percent:100` and requests extension pace `1`. It leaves the native driver/car factors unchanged, including values above1. Observer Off/100 acknowledgement means no authored publication substitution; it does not mean the game's factor is1. The page requires the optional `nativeCornerTarget` capability before owning this mode. It keeps node targets lower-only, parks legacy power/grip while owned or reset is pending, and clears selection on Stop, manual takeover or profile Load. The controller's generic On interface below is dormant in the active page.

The browser API is `__NFSU2_RUBBERBAND_CONTROLLER__.Controller` (also CommonJS). Construct with `(memory, {installed:true, verified:true, moduleHash, moduleIdentity, protocol?})`; the default protocol is `__NFSU2_NATIVE_RUBBERBAND__`. Exported `MAX_PERCENT=150` bounds the dormant authored assist API; it is neither an active-mode setting nor a claim about a universal native rubberband maximum.

Call `update({enabled, safe, ordinaryRace, network, allowNetwork, aiState, currentCar, percent, selectedPace, featureOwnsPace, customPower, customGrip, customBoost?, customUnlimit?, now})` continuously, including while disabled. Use one monotonic clock domain. `aiState` is the existing AI controller's `{active, owned}` status. Neutral custom power/grip must be numeric `1`; optional boost/unlimit/grip flags, when present, must be literal `false`. On additionally requires exact selected pace `percent/100` and literal feature ownership. The controller does not modify saved preferences.

`update` returns a frozen status with `state`, `reason`, `active`, `requested`, `commandEnabled`, `command`, `requestedPercent`, `appliedPercent`, `currentCar`, `publication`, `ackAgeMs`, `resetPending`, `resetAcknowledged`, `supported`, and `verified`. `status(now?)` returns the latest status, expiring evidence when a current clock value is supplied.

Applied requires reason 1, the current command and car, and an advancing coherent publication observed within 1,000 ms. A first matching acknowledgement without a known baseline only establishes that baseline. Unchanged receipts do not renew freshness. Reason 3 / 100% reports `guarded-native`, never an Off acknowledgement. Polling gaps over 1,000 ms force a new command generation, preventing old publications from being redated as current.

`stop(input?)` issues Off with one forced generation per stop episode, then reports `reset-pending` until an advancing current-car Off publication. Repeated stop calls do not churn generation. Stop remains latched until a subsequent ordinary `update` observes `enabled:false`, followed by `enabled:true`. Continue polling after manual handback/pause; no former AI/race pointer is needed for Off. Memory, buffer growth, car, module hash or identity changes clear evidence and never cause writes to the former memory. Optional binding replacements can be supplied directly to `update`.
